Version: 2026-06-05
Summary: Added enhancement-folder training support and raw `.txt` email ingestion for adversarial data.

What was added
- `generate_data.py` now supports `.txt` emails under labeled folders and treats text files in `enhancements/phishing` as phishing and `enhancements/false positive` as ham.
- `train.py` now automatically includes `enhancements/` along with `Datasets/` when no explicit `--dataset-paths` are provided.
- `scripts/validate_pipeline.py` now also auto-includes `enhancements/` so validation uses the same enhanced training data.

What was changed
- `generate_data.py`: added raw text file ingestion (`.txt`) and directory-based label inference from parent folder names.
- `train.py`: updated default dataset handling to include `enhancements` automatically when present.
- `scripts/validate_pipeline.py`: updated dataset path resolution so validation uses the same enhancement data as training.

Usage
- Place crafted adversarial examples in `enhancements/phishing/*.txt`.
- Place false positives in `enhancements/false positive/*.txt`.
- Retrain with `python train.py` and validate with `./scripts/validate.sh`.

Version: 2026-06-03
Summary: Finalized expanded dataset retraining and validation, resolved Git LFS dataset issues, and consolidated changelog entries into a single update.

What was added
- Git LFS support and `git lfs pull` to fetch actual CSV data for `Datasets/Phishing Email Dataset`.
- `text_combined` support in `generate_data.py` so `phishing_email.csv` can be parsed.
- End-to-end validation workflow via `scripts/validate_pipeline.py`, `scripts/validate.sh`, and `validation_report.txt`.
- Verified model artifact loading, `agent.py` scan behavior, and attack demo baseline.

What was changed
- `generate_data.py`: added `"text_combined"` to `TEXT_COLUMNS`.
- `train.py`: clarified that `Datasets` is scanned recursively, so nested sources under `Datasets` should not be passed again as separate paths.
- `CHANGELOG.txt`: merged multiple intermediate updates into one consolidated release note.

Difficulties encountered
- Git LFS pointer files hid actual CSV data until `git lfs pull` was run, so dataset ingestion initially skipped large files.
- `phishing_email.csv` used a nonstandard `text_combined` field, requiring loader extension.
- Passing both `Datasets` and nested `Datasets/phising-dataset` duplicated dataset rows; the correct recursive path is `Datasets` alone.
- The expanded dataset includes JSON list files and required careful loader validation.

Data difference
- Original baseline snapshot: ~176,972 rows from the smaller dataset.
- Expanded dataset loaded recursively from `Datasets`: 1,032,806 rows.
- The current dataset is roughly 6x larger than the earlier baseline, giving the model much broader phishing and ham content.

Training progression
- Baseline training on the original smaller dataset: 141,577 samples, Accuracy 0.9831, F1 0.9839.
- Expanded training on `Datasets` with recursive ingestion: total dataset rows 1,032,806, Train: 826,244, Test: 206,562.
- Final metrics: Accuracy 0.8885, Precision 0.9207, Recall 0.8378, F1 0.8773.

Validation result
- `./scripts/validate.sh` completed successfully and wrote `validation_report.txt`.
- `python scripts/validate_pipeline.py --dataset-paths Datasets --output validation_report.txt` confirmed the artifact loads, the agent scan works, and the attack demo failed to flip the current model.
- Avoid passing `Datasets` and nested `Datasets/phising-dataset` together unless deduplication is added.

Notes
- The larger dataset improved coverage and reduced inflated metrics from the smaller baseline.
- The attack demo failure is a useful baseline for future evasion testing.

Next steps
- Share the trained `phishing_model.joblib` with the team via GitHub Release or cloud storage.
- Sebastian (Data) can verify the dataset parsing quality and report any remaining data issues.
- André (Attack) can now request the artifact and run evasion experiments.
